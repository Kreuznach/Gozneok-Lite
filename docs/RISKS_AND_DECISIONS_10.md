## 주요 결정 기록

### D-01: 상태관리 라이브러리 없음 → React Context만
- **결정**: Redux, Zustand 모두 MVP에서 제외
- **이유**: 번들 크기 최소화, 복잡도 회피
- **리스크**: 컴포넌트 수가 많아지면 Context 드릴링 발생 가능
- **대응**: 필요 시 Zustand 도입 (확장 단계)

### D-02: TourAPI serviceKey → 서버 ENV 전용
- **결정**: 클라이언트에 키 절대 포함 금지, Node 프록시 서버만 사용
- **이유**: 보안 (키 유출 시 쿼터 소진/과금)

### D-03: 지도 SDK 미사용
- **결정**: MVP에서 지도 임베드/SDK 없음. 카카오맵 외부 링크만
- **이유**: 번들 증가, Toss 심사 리스크, iframe 금지

### D-04: 더미 데이터 폴백 구조 유지
- **결정**: TourAPI 장애 시 20개 더미 데이터 반환
- **이유**: 심사/테스트 단계에서 API 오류에도 앱 기능 확인 가능

### D-05: Quiet Score 레이블 — 단정 표현 금지
- **결정**: "대체로", "경향" 표현만 사용
- **이유**: 심사 및 소비자법 준수 (사실과 다른 광고 표현 방지)

### D-06: 위시리스트 localStorage만 (MVP)
- **결정**: 서버 위시리스트 동기화는 확장 단계
- **이유**: DB 연동 복잡도 최소화, 익명 사용자 기준

### D-07: Debug 페이지 동적 import
- **결정**: `lazy()` + `import.meta.env.DEV` 조건부 라우트
- **이유**: 프로덕션 번들에서 자동 제외, 심사용 빌드 일관성

### D-08: 광고 그룹 ID 환경변수 분리
- **결정**: `VITE_ADMOB_*` 환경변수로 분리, 미설정 시 광고 비활성화
- **이유**: 심사/개발 환경에서 광고 없이 동작 확인 가능

### D-09: 투표 쿨다운 24h (deviceId 기준) → **[변경] v2 이후 구현 예정**
- **결정 변경**: 투표 기능 자체를 MVP 범위에서 제외 (2026-02-19)
- **이유**: 심사 단순화, Quiet Score 데이터 없이도 앱 동작 가능, v2에서 서버 DB 연동 후 재구현
- **영향 범위**: PlaceDetail (투표 UI 제거), storage.ts (vote 함수 제거), api (POST /api/votes 제거)

### D-10: 모노레포 구조 채택
- **결정**: apps/web + apps/api pnpm workspace
- **이유**: 코드 공유 가능, ENV 격리, 배포 독립성
